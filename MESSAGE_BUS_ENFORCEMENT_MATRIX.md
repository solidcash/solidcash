# Message-Bus Compact Binder Enforcement Matrix

This is the implementation audit for the replacement (`L3V1` commitment prefix, `L3B1` binding preimage)
described in `MESSAGE_BUS_BYTECODE_IMPLEMENTATION_PLAN.md`. Source locations are intentionally named rather than
line-numbered: the generated source is recompiled and source-map/optimizer changes must not invalidate the proof.

| Invariant | Enforcing owner and opcode path | Why it executes / adversarial coverage |
| --- | --- | --- |
| Exact verifier covenant | The compact master generated by `compiler.ts:createMessageBusVerificationFunction` checks `tx.inputs[activeVerifier].lockingBytecode == offloadedVerifierLock`. This lowers to `OP_UTXOBYTECODE` plus `OP_EQUALVERIFY`. | The active master input executes this route. Its artifact has the specialized P2SH32 locking bytecode embedded, so a same-category lookalike cannot satisfy it. `AtomicMessageBusCompose` mutates the verifier locking bytecode. |
| Verifier/master category association | The same compact master requires the verifier category's 32-byte category portion to equal the active participant category and requires mutable capability `01`. | Both values are transaction introspection results at the selected input. Replacing a verifier with another pool/category fails before a digest is read. |
| Exact verifier input/output pairing | The compact master takes the verifier output at the same `activeVerifier` index; the generic sidecar in `message-bus-verifier.ts:buildMessageBusVerifierCovenantScript` recreates its own input at `OP_INPUTINDEX` using `OP_OUTPUTBYTECODE`, `OP_OUTPUTTOKENCATEGORY`, `OP_OUTPUTTOKENCOMMITMENT`, `OP_OUTPUTTOKENAMOUNT`, and `OP_OUTPUTVALUE`. | The master cannot select a separate output, and the selected verifier input must execute its self-recreation tail. Output commitment and locking-bytecode mutation cases are exercised in `AtomicMessageBusCompose`. |
| Supported verifier commitment states | The generic sidecar accepts only a 6-byte genesis or 70-byte recurrent commitment, splits the six-byte prefix, verifies `L3V1`, and always concatenates prefix, current manifest digest, and current binding. | The test suite exercises recurrent spend and compact 70-byte output commitments. Stale recurrent tails are discarded, never evidence. |
| Canonical envelope and manifest | Every specialized verifier program derives `expectedMessageEnvelopeHash` from the positional final verifier input (`tx.inputs[tx.inputs.length - 2]`). The generic sidecar requires the 96-byte return and checks `OP_SHA256(itsOwnMessageEnvelope) == expectedMessageEnvelopeHash`. | This forces all participant verifiers onto one manifest even though each carries its own envelope push. Swap, drop, duplicate, coordinated rewrite, and one-verifier-only divergent/rebound mutations are covered by `AtomicMessageBusCompose`. |
| Manifest digest provenance | The full verifier computes `sha256(callManifest)` after canonical parsing and returns it as result two. The generic sidecar stores that exact return in the output commitment. | It is never a user-provided master ABI argument. The compact master reads the fixed middle 32 bytes of the exact selected verifier output. |
| Local batch/graph binding | The compact master recomputes `sha256(L3B1 || manifestDigest || activeMasterInputIndex || rows || sha256(localBatch) || mode || graphFields)` from its actual route arguments and compares it with the last commitment field. | A digest copied from another master index, changed local batch, graph field, or manifest fails at the master. `mutateAuthenticatedFrame` repairs attacker-controlled commitments before testing rejection. |
| Master in-place recreation | The compact binder checks `activeInputIndex < tx.outputs.length` and its direct master output/commitment preservation path runs at the same master index. Ordinary stateful route covenants own unchanged lock/category/value/token payload constraints. | Participants are assembled at their declared physical block offsets. Mapping/event/chunk settlement tests mutate the resulting output and reject. |
| Verifier cardinality and ordinal preservation | After invoking the specialized verifier, the generic sidecar performs a transaction-wide class balance over its exact locking bytecode and full token category: matching inputs increment, matching outputs decrement, and `OP_NUMEQUALVERIFY` requires zero. It then recreates its own ordinal-bearing commitment at `OP_INPUTINDEX`. | Every accepted verifier input necessarily executes this generic tail. The class balance rejects an added output clone even if a fee output is replaced and all ordinary economic checks remain valid; `AtomicMessageBusCompose` exercises that mutation. Pool selection remains fungible, while the composer reserves selected outpoints so one UTXO cannot fill two physical verifier slots. |

The compact master deliberately does **not** parse `OP_INPUTBYTECODE`: the manifest carrier is the exact verifier
output NFT commitment. This is asserted by `MessageBusVerifierSize.test.ts` and prevents a master from paying
`OP_INPUTBYTECODE`/`OP_SPLIT` byte-proportional cost to recover the digest.
